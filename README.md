### TUGAS 5

1. Debouncing adalah teknik untuk menunda pengiriman request sampai pengguna berhenti melakukan input selama waktu tertentu. Pada fitur pencarian yang menggunakan AJAX, debouncing penting karena tanpa debouncing setiap perubahan karakter saat pengguna mengetik dapat langsung mengirim request ke server. Dengan debouncing, request hanya dikirim setelah pengguna berhenti mengetik sehingga jumlah request yang dikirim lebih sedikit dan proses pencarian menjadi lebih efisien.
2. `await` digunakan untuk menunggu Promise dari `fetch()` selesai sebelum kode berikutnya dijalankan. Dengan menggunakan `await`, hasil dari `fetch()` dapat langsung disimpan ke dalam variabel `response` dan kemudian diproses, misalnya dengan memeriksa `response.ok` atau membaca hasil JSON menggunakan `response.json()`. Jika tidak menggunakan `await`, `fetch()` langsung mengembalikan Promise sehingga kode berikutnya dapat dijalankan sebelum response dari server tersedia.
3. XSS (Cross-Site Scripting) adalah serangan ketika data yang tidak aman disisipkan ke halaman web dan kemudian dijalankan sebagai kode oleh browser. Data yang ditampilkan melalui AJAX/JavaScript lebih rentan jika data tersebut langsung dimasukkan ke HTML, misalnya menggunakan `innerHTML`, karena isi data dapat diperlakukan sebagai markup HTML. Oleh karena itu, setiap nilai teks yang disisipkan melalui JavaScript perlu di-escape agar karakter khusus seperti `<` dan `>` tidak diperlakukan sebagai tag HTML. Pada template Django, data yang ditampilkan menggunakan template variable pada umumnya sudah melalui mekanisme escaping bawaan Django, sedangkan ketika data dari AJAX dimasukkan sendiri ke HTML melalui JavaScript, developer harus melakukan escaping secara eksplisit, seperti menggunakan fungsi `escapeHtml`.

### TUGAS 6

1. REST (Representational State Transfer) adalah sebuah gaya arsitektur untuk membangun API yang menggunakan resource sebagai pusat interaksi. Setiap resource memiliki alamat atau endpoint sendiri dan dapat diakses menggunakan HTTP methods seperti GET, POST, PUT, PATCH, dan DELETE. Mengembalikan JSON saja belum cukup untuk menyebut sebuah API sebagai RESTful karena JSON hanya merupakan format pertukaran data. API juga perlu menerapkan prinsip-prinsip REST, seperti penggunaan resource yang memiliki URI, penggunaan HTTP methods sesuai fungsinya, stateless communication, serta penggunaan HTTP status code yang sesuai dengan hasil operasi. PUT digunakan untuk memperbarui keseluruhan representasi suatu resource. Sementara itu, PATCH digunakan untuk memperbarui sebagian atribut dari suatu resource. Contohnya, ketika ingin mengganti seluruh informasi sebuah Experience, PUT dapat digunakan dengan mengirimkan seluruh field yang diperlukan. Namun, jika hanya ingin mengubah deskripsi Experience tanpa mengubah judul atau organisasi, PATCH lebih tepat digunakan karena hanya field yang ingin diubah yang perlu dikirimkan.
2. Serializer pada Django REST Framework berfungsi untuk mengubah objek model Django menjadi representasi data yang dapat dikirimkan melalui API, seperti JSON. Serializer juga dapat melakukan proses sebaliknya, yaitu mengubah data masukan dari request menjadi data Python yang dapat digunakan untuk membuat atau memperbarui objek model. Penggunaan serializer memiliki beberapa keuntungan dibandingkan merakit dictionary secara manual menggunakan JsonResponse. Serializer menyediakan proses serialisasi dan validasi data secara terstruktur, sehingga kita tidak perlu menuliskan konversi setiap field secara manual. Serializer juga mendukung validasi bawaan maupun validasi khusus melalui method seperti validate_<field>(). Selain itu, ModelSerializer dapat mengambil struktur field langsung dari model sehingga implementasi menjadi lebih ringkas dan mudah dipelihara. Pada Tugas 6, ExperienceSerializer digunakan untuk mengatur field yang dapat diakses melalui API, melakukan validasi input, serta menyediakan informasi tambahan seperti star_count dan is_starred.
3. Autentikasi adalah proses untuk memastikan identitas pengguna yang melakukan request. Pada Django REST Framework, autentikasi dapat dilakukan menggunakan session sehingga server dapat mengenali pengguna melalui session yang sedang aktif. Sementara itu, otorisasi adalah proses menentukan apakah pengguna yang sudah terautentikasi memiliki izin untuk melakukan suatu tindakan. Contohnya, pengguna biasa hanya dapat melihat dan memberikan star pada Experience, Editor dapat melakukan perubahan data, sedangkan superuser memiliki hak akses penuh. Pemeriksaan hak akses harus dilakukan menggunakan permission class di server karena tampilan frontend bukan mekanisme keamanan. Menyembunyikan tombol Edit atau Hapus di template hanya membatasi apa yang terlihat oleh pengguna. Pengguna tetap dapat mencoba mengakses endpoint API secara langsung menggunakan browser atau HTTP client lainnya. Dengan permission class, server akan memeriksa izin pada setiap request sebelum menjalankan operasi. Dengan demikian, pengguna yang tidak memiliki hak akses tetap akan mendapatkan respons HTTP 403 Forbidden meskipun mencoba mengakses endpoint secara langsung.
4. SessionAuthentication menggunakan session dan cookie untuk mengenali pengguna yang sedang login. Browser secara otomatis mengirimkan cookie session ketika melakukan request ke domain yang sesuai. Hal ini menimbulkan risiko Cross-Site Request Forgery (CSRF), yaitu kondisi ketika situs lain mencoba membuat browser pengguna mengirimkan request yang tidak diinginkan menggunakan session pengguna tersebut. Token CSRF digunakan untuk memastikan bahwa request yang mengubah data memang berasal dari sumber yang memiliki token yang valid. Oleh karena itu, operasi seperti POST, PUT, PATCH, dan DELETE perlu menyertakan token CSRF melalui header X-CSRFToken. Pada implementasi Tugas 6, token CSRF dikirimkan melalui header pada setiap request yang mengubah data menggunakan Fetch API. Pengujian CSRF juga penting dilakukan menggunakan APIClient dengan enforce_csrf_checks=True. Penggunaan force_authenticate() saja tidak cukup untuk membuktikan perlindungan CSRF karena metode tersebut melewati proses autentikasi session normal yang digunakan dalam pengujian tersebut.
